## 贯穿全程的四条做法

1. **真数据验证**：能打到用户在用的真库与真账号上，就不停在隔离环境里自证。档案的曲线、回放的节点时间线、推荐卡片的命中率，全部经过真库只读验收；smoke 脚本只是补充证据。
2. **机械判据**：不说"看起来对"。语音转写与素材比字符重合率；图是否被模型读到，靠图内埋独有标识串、断言后续文本引用它；"帧不上传"靠 CDP Network 域零新增请求证明；暗色主题靠像素采样而不是看图。
3. **单一来源**：凡是"两处算同一个东西"，抽成一份实现并写测试钉死——总分口径、检索 doc 文本、评测与生产共用的评分 prompt、决策与原因同源的 `explain_decision`。同一批数字两个来源，迟早会不一致。
4. **诚实的边界**：没覆盖的就写"未覆盖"（真实白板照片、移动端布局、多 worker 下的熔断状态）；降级就如实标注而不是静默掉质量；没验证过的结论不下。

## 阶段 1：demo 最小闭环（T1–T7b，2026-09）

先把"一场面试能从头跑到尾"这条链路打通：语料管道（个人题库三格式解析 → 结构化 JSON）→ RAG（BGE-M3 嵌入 + Qdrant 每题一 doc）→ LangGraph 五阶段状态机（追问决策、checkpointer 断线续面）→ FastAPI + SSE 流式接口 → Next.js 面试页与报告页 → Docker Compose 一键起。

**验证**：完整跑完一场 15–20 分钟面试；刷新页面可续面；追问行为可用单测断言状态转移。

这一步定下了两条后来一直在用的纪律：**确定性逻辑（阶段推进 / 轮数 / 追问决策 / 配额）全部用代码写死**，LLM 只做语义任务；**结构化输出 = 关 thinking + `json_object` + schema 注入 prompt + Pydantic 校验**（`json_schema` 实测 400，不可用）。

## 阶段 2：功能完善（P1-M1 – P1-M12，2026-09 ~ 10）

### P1-M1 · 面试复盘与回放，报告切 v4-pro
报告 payload 逐题增复盘字段（回答分段 / 五维 / 关键点 ✓✗ / 参考答案），已结束场次只读回放，报告节点换深度模型。
**踩到的第一件事**：契约写了"回答含追问轮"，而数据层从来没存过——首答在 state 里根本不存在。做"复盘 / 回放 / 导出"类需求，第一步是查数据层到底存了什么。
**同一批修掉的**：`chat_history` 有个 24 条截断，而回放与 SSE 长度差分两个消费者都依赖它"只增不减"——10 轮多追问的场次实测写入 67 条只留 24 条，34 条面试官文案发不出去。短用例刚好卡在边界上测不出来。

### P1-M2 · 账号体系（JWT + 多用户隔离）
后端 `security.py`（scrypt + PyJWT）+ 六端点挂鉴权与归属校验（他人场次一律 404）；前端登录注册页、路由守卫、统一 401 处置。
**两处值得记的**：401 必须"先清 token 再交给跳转策略"并封进唯一入口——顺序反了会在"token 失效但仍存在"这一种状态下死循环；"首次触发即改变既有数据"的逻辑（首注册会认领历史场次）只能在副本上测，正式库只做读操作。

### P1-M3 · 混合检索底座（本地 BGE-M3 双向量 + RRF + rerank）
独立 embedding 容器（一次前向出稠密 + 稀疏，省掉独立 BM25）；ingest 改命名双向量重建；`hybrid_search` = embed → 双路 prefetch → 服务端 RRF → SQLite join → SiliconFlow rerank。
**关键取舍**：rerank 要用题干+关键点，而 Qdrant payload 里刻意没有正文 → join 必须排在 rerank 之前（管线顺序跟着数据依赖走，不跟着口头表述走）。镜像瘦身 9.34GB → 5.72GB 且新旧镜像对同一文本的向量指纹逐位一致——瘦身零行为代价。

### P1-M4 · 决策回放 + Langfuse 可观测（FR-21）
`state.trace_log` 六型事件 + 六个节点埋点 + `explain_decision`（**决策与原因同源**）+ `GET /interviews/{id}/trace` + 回放页。
**踩到的**：Langfuse v4（OTel 重写）与网上 v3 教程是两套 API，照抄博客时"错的每一行都像对的"；成本为 0 不是接入坏了——它靠项目侧价格表算钱，且价格表生效前的观测永久为 0、不追溯。

### P1-M4.5 / M4.5-R1 · 出题接上下文、深挖追问、追问密度修复
出题接 `candidate_profile` 与三条防漂移约束；追问新增深挖分支（题库题直接发预置追问素材、零 LLM）。
**真链路暴露的问题**：一场 3 题追问了 10 次。根因不是预算而是"反复问同一个漏点"——去重单元改为已追问的关键点集合，另加全场补救池预算。同是 2 题坏回答：修复前 19 个决策事件 → 修复后 11 个。

### P1-M4.7-D · 面试官"人味层"（六类衔接语 + 技术题同域成块）
高频短衔接全部零 LLM（模板 + 插槽 + 按轮次轮换变体），只有开场白与结束陈词走 LLM、每场两次；技术段改为同域成块。
**在这里补的两条**：结束陈词模板**结构上不接任何输入** + prompt 写死四条禁止（生成式文案的红线是试出来的——真链路跑出"后续会有同事联系你"这类变相表态才补上）；关键路径末尾的"锦上添花"调用失败不连坐产物（陈词挂了照常出报告）。

### P1-M5 · 多源 provenance 拆表 + 开源语料扩充
`questions` 只留答案主源，四要素明细迁入 `question_sources`（license 按源记）；接入四源 MIT 语料，题库 342 → 1571 题（enabled 1095），Qdrant 重建 1095 点。
**两个前提被真数据推翻**：一条"去重留第一条"的直觉让存根挤掉了正本，7 题的出处指向别处——拆表类改动的验收必须按字段逐行比，行数对得上说明不了问题；另一条更贵：规划的语料源里有一个仓库实际**不含任何题目数据**（只是采集框架），一个错误前提改了整个会话的方案。
**事故与修复**：宿主机跑的 smoke 直连真库 WAL 库，把 checkpointer 写坏（全线 500）。分界线在 journal 模式不在"是不是跨进程"——业务库是 rollback journal，宿主机反复跑都没事；WAL 库一碰就碎。修法是 smoke 补临时路径隔离 + 防呆断言。

### P1-M6 / M7 · 题库页与容量校验、私有题库
`/bank`（混合检索 + 四维分面 + 来源四要素）与 `/bank/private`（模板上传、部分成功语义、混入式出题）。容量校验只做前端展示判据、**绝不拦创建**（直供不足 ≠ 出不了题，引擎有难度放宽与 LLM 生成兜底）。
**私有题与公共题同表**，故公共侧所有查询都要加 `user_id IS NULL`；顺带拆掉一颗雷——ingest 的全量同步删除会把私有题一起删光（私有题永不在管道产物里），两个 DELETE 收窄到公共行并用回归测试钉死。

### P1-M8 · 报告导出 PDF（FR-18）
服务端渲染真文本 PDF（weasyprint + 手绘雷达 SVG + RFC 5987 中文文件名），`asyncio.to_thread` 现渲染不落盘。"中文无乱码"的判据 = pypdf 读回无替换字符 + 关键串命中。
**一次被压掉的真信号**：转换预览工具里近一半汉字不见，我判成"预览器认不了子集字体"，用户随后报浏览器打开乱码。真因是字体栈只写在 `body` 上，而页边距框与 SVG `<text>` 不继承它。"在我机器上渲染正常"是最弱的证据——判据要落到"字体的来源"。

### P1-M9 · 学习推荐（FR-20）
报告的短板域与漏点关键词直接驱动检索推题——不重算分数、不落库、零新增 LLM 调用（题库更新即新鲜）。排除本场已问、按域保序并发、空分组如实说明而不是隐藏。
**真数据带出的一次架构级修正**：漏点是叙事型时推荐明显退化，追下去发现技术域里混着 10 道"项目叙事题"——它们的 key_points 是讲述结构不是知识点。修法不是调检索，是治最上游：建人工改判表把它们摘出技术域（改判在零回归校验之后执行，幂等）。链路是「题目形状 → 漏点形状 → 查询形状 → 检索结果形状」，一环坏一环。

### P1-M10 / M10.5 · 能力档案与前端改版
`GET /api/profile` 多场聚合（以 reports 表为准、升序定时序、无场次返回零态结构而非 404）；前端三视图：总分曲线、知识域热力图（缺场写"未考"）、短板变化。
**总分口径收敛**：报告页、PDF、档案三处此前各算一遍五维均值——判据是"新增消费方时，如果需要自己算一遍才能拿到某个业务数字，这个数字本来就该由上游产出"。**缺数据不补零**：曲线缺场断开而不是画成 0 分，否则会凭空造出不存在的低谷。

### P1-M11 · 行为面 / HR 面（FR-22）
`interview_type` 与岗位正交，贯穿 DB → state → 报告 payload；复用同一状态机，只换能力模型（五维）与题源；追问改 deepen-only（行为题的要点是讲述结构，"补漏"语义不成立）；难度保留机制但作死数据；能力档案排除行为面并如实说明。
**一次真实事故**：新写的集成测试文件重定义了 conftest 的同名 fixture，把 DB 路径注入整个覆盖——测试直连了正式库并注册了测试账号。核对计数后删除、零残留。此后立下纪律：**凡测试碰库，跑完回头数正式库行数**。

### P1-M12 · 离线评估体系（会话 1 检索 / 会话 2 评分）
**检索侧**：31 条 golden 查询 × 1972 条标注，四变体（dense / sparse / rrf / hybrid）基线 + RAGAS 内容相关性。评分 rubric 第一版太宽（74% 候选判相关、指标失去分辨力）→ 加反例收紧到 52%。
**评分侧**：选型修正——原计划 DeepEval，实测它没有现成的一致性 / 准确性 metric，改为自研 harness（37 条 golden × 每条 5 次运行）。基线 σ̄ 0.113、MAE 0.225（≈ 2 倍晃动，误差大于晃动、信号成立）、三档单调 3/3，**门禁阈值 = 基线 + 余量，余量取自指标自身的波动**（×2–4），超限非零退出。
**三条方法论**：先量噪声地板再读 MAE（顺序反了就是拿噪声当结论）；噪声比要抓的退化还大的指标（完全一致率）不进门禁；评测的 prompt 必须是生产那一份并用测试钉死逐字一致。

### 收尾专项（2026-10-02）
视觉大扫除（设计令牌归一、6 个共享件、状态态 7→1 / 6→2 / 5→3 档）+ README 门面重写 + 文档系统性核对 + MIT LICENSE。顺带修掉一个"装了没 import"的依赖——弹窗动画的 CSS 一直在空转，构建产物里根本没有这些规则。

## 二期：多模态与企业级收尾（P2-M1 – P2-M12，2026-10）

### P2-M1 · 题库质量三连
难度重标注 1002 题（容量网格 11/12 → **12/12**）、近似重复 3 对措辞级合并、行为题补讲述要点。
**先量后用**：四源里只有一源带真实难度标注，另三源的"L2"是解析器默认值——**"没有标注"与"标注成 L2"在生产数据里长得一模一样**。拿唯一有真标注的 89 道当校准集验证 rubric（完全一致 68.5%），过关才全量。**缺口的形状决定方案**：L3 直供不足看着是"L3 总量太少"，实际缺口域 22 题全在个人题库，只标开源语料永远补不上那一格。

### P2-M2 · 检索与推荐修复
rerank 对多漏点长查询实测**净贡献为负**（−0.152），改为按查询形态开关：长查询走融合序、短查询保留 rerank——missed_point NDCG@5 0.660 → **0.813**。学习建议的域字段改结构化（prompt 注入合法清单 + 落库前宽容归一，绝不抛错——一个建议字段不值得炸掉整份报告）。
**规划里认真选的兜底方案也可能是错的**：备选方案实测比原方案还差，三种形态各跑一次评测（每次 ~2.5 分钟）比在方案上争论便宜得多。

### P2-M3 · 前端小修包
窄屏顶栏换行（原实现五个 tab 挤一行、每个被压到 30px 宽、标签逐字竖排）、能力档案补"报告缺失场次"说明与空态第三态、私有题库禁选行为面升到接口层断言。
**这里发现一类判据盲区**："页面不横向滚动"查不出 flex 压缩型破版（是压缩不是溢出），判据得看"item 高度 / 行数"。

### P2-M4 · 模态层 + 真 token 流
`chat()` 改流式聚合（不另起一套实现）、SSE 新增 `delta_start` / `delta_chunk`（`delta` 语义不变，旧前端照常工作）、前端流式渲染并保留打字机兜底。**唯一动引擎处**是服务层多收一路 custom 流映射成 SSE——图结构、状态机、落库、重连语义一条未动。
**15 分钟探针关掉了规划里的头号风险**：最担心"Langfuse 对流式读不到 usage → 成本归因断"，实测完全支持。真链路 TTFT 0.47s。**判据是"渲染早于流结束"**，不是"字数在涨"——旧打字机同样在 busy 期间吐字，两者采样下分不出来。

### P2-M5 · 语音面试（FR-24）
`WS /api/asr` 中继豆包流式识别 + `POST /api/tts`（edge-tts）；转写实时落输入框、**发送前可编辑**；TTS 三档降级（edge-tts → 浏览器合成 → 纯文字）。**引擎零改动**——语音只是新增一条音频通道。
**凭据与协议各撞两次**：两把火山 key 不通用（方舟 Bearer ≠ 豆包语音 X-Api-Key），三种失败形态各不相同；二进制协议里配置帧占 1 号序号（音频从 2 起）、末帧不带序号字段，两个"差一位"的坑各撞一次。**"能不能开始"与"能不能结束"是两条判据**——录音键写成"不可开始"的判据，结果是录音中按不停。

### P2-M6 · 视觉通道（FR-26）
代码截图随回答上传，评分官看图、生成题结合上一题的图。**核心设计 = 图独立成一条附件消息、不改任何既有 prompt 模板**——无图调用的消息列表与接入前逐字一致，于是"无图零回归 + 评测门禁零漂移"是**构造上成立**的，不是测出来的。
**探针先行扭转了两处设计**：DeepSeek 视觉的内容块必须是对象（裸字符串 422）；图按像素计费，800px 掉可读性、1568 是性价比拐点。**"图有没有被模型读到"用机械判据**：图内埋标识串，断言后续文本引用它（真链路里收尾回答直接引用了图内的 `scratchpad`）。

### P2-M7 · 摄像头 UI 模拟 + 面试间整合（FR-27）
**纯前端，后端零改动**。面试页改成"双人舞台 + 控制条"：面试官人像框与我的画面等大并列，状态徽标全部由现有状态派生（零新状态、零后端字段）。**摄像头是 UI 模拟：帧不上传、不落库、AI 不看**——全仓画面只有 `getUserMedia → video.srcObject` 一条路，没有 canvas、没有抓帧、没有上传函数。
**"没有发生"的承诺用"没有请求"证明**：CDP Network 域确认画面播放 4 秒内零新增请求。顶部形态经四轮迭代（浮窗 → 区域带 → 卡片 → 护栏），**"区域"与"物件"是两种读法，面积和边界形态决定它被读成哪一种**。

### P2-M8 · 端到端验收 + 文档同步
零生产代码改动。新增组合场 smoke：**一场里**同时跑语音进（TTS 合成 → 走应用层 WS 转写 → 作为答案提交）/ 语音出 / 截图 / 文字，并断言转写文本出现在报告复盘卡里——把"语音只是录入口"证成"语音真的进了引擎"。浏览器组合验收 29/29，闭合了 M7 留下的两条未覆盖面（结束即关画面、SPA 卸载收摊）。

### P2-M9 · 可靠性工程
并发闸门（持有期 = 整流生命周期）+ 熔断（半开只放一个探针）+ 降级链。**只有"上游不可用"类失败才降级**（连接 / 超时 / 429 / 5xx / 熔断），内容类与配置类失败原样抛回走既有重试语义——把已知的偶发非法 JSON 降级成"未评分"，等于把可恢复的故障静默成质量下降。
**降级 = 照常走完 + 如实标注**：开场 / 出题 / 评分 / 报告全部走确定性兜底（**不调 LLM**），且"未评分不产 0 分"（报告不落分数键、能力档案排除并说明）。如实交代是**四处**而不是一处：SSE 事件 / 会话状态 / 报告 payload / PDF——任何一处单独存在，都会在某个进入路径上变成静默。验收 = 假上游一律 503，一场完整面试 25 秒走完、零 SSE error、PDF 照常导出。

### P2-M10 · CI + MCP 题库查询 + 成本归因
GitHub Actions 三 job（后端 pytest / 前端 lint+vitest+build / 语料入库守卫 + 检查器自检）。MCP server 把题库检索暴露给任意 MCP 客户端：**stdio only、只读、只公共题**，协议代码关在一个包里（单测扫描钉死别的模块不许 import `mcp`）。成本按调用环节命名，`cost_report.py` 按场次读回。
**CI 首跑四红，全是"环境差异"的四种形态**：缺假密钥（84 个用例 ValidationError）、时区（测试断言"本机在 UTC+8"）、缺系统件（PDF 渲染要 pango 与 CJK 字体）、**本机跑着的服务**（一个测试忘了打桩、真的去打了本机 Qdrant，CI 里没有就红）。而"干净副本预演"只抓到第一种——**预演要造一个"不像本机"的环境，不是复制一份自己**。
**红线检查器自己查出过一个真 bug**：关键点在库里是 JSON 文本，原实现把它当列表展开、字符串被拆成单字——**关键点一条都没参与比对，而检查全绿**。修好后语料覆盖面从 53k 涨到 61k 个比对窗口。这类"顺手展开字符串"的写法不报错、只静默少查一路。

### P2-M11 · 简历分析（FR-28）
上传或粘贴简历 → 结构化抽取 → 预填候选人背景 → **出题侧零代码改动就变具体**；文件与粘贴文本走同一端点、同一抽取管线（扫描版 PDF 抽不出字时明确报错指路，绝不静默退化成"没传简历"）；只回结构化结果、不回原文。项目深挖题改题库优先（题库题自带关键点与预置追问素材）。
**"预填一个插槽"的验收要看下游产物**：机械判据是面试官文案必须引用只存在于简历里的标识串，而不是断言 state 里有值。**提示词的语气就是可测性**：写成"可以点名项目"（许可语气）→ 模型大概率不点名、判据没信号；改成"要**点名**"后首跑即命中。

### P2-M12 · 节点级 Trace
回放页逐轮卡片**之上**新增节点时间线：每步的节点 / 时长 / 状态变化，**零写入**派生自 checkpoint 历史——不建表、不改 state、不改节点，并补上决策事件里完全没有的节点（开场 / 自我介绍 / 等待输入）。
**探针先行的三个反直觉发现**：节点名的唯一现成来源是前一个存档的 `next`（checkpoint 元数据里没有写入记录）；值 diff 会漏——异步落盘让节点开头的原地修改渗进上一步的存储值，故写入 = 该存档记录的写入 ∩ 这一步真变了的通道；等待输入那一步天然包含用户的真实思考时间（真数据里最长的一步 40 多小时）。
**随行修掉一条概率性断言**：上一件工作让某条冒烟断言的前提变了，它的通过率掉到 1/8，而**绿一次说明不了问题**——概率性断言与确定性断言长得一样。
