# 评估基线（P1-M12）

> 这是**可进仓库**的那一份：只有数字与结论，**不含题面**。含题面的产物
> （`golden/review.md`、`results/`）按语料红线留在本地，见仓库根 `.gitignore`。

## 是什么

`backend/evals/` 是离线评测包（**只被 `scripts/` 调用，`app` 永不 import**）。评测**不进 pytest**——
它要真 Qdrant + 嵌入容器 + LLM，而常规用例必须保持无密钥可跑。契约见 SPEC §4.13。

会话 1 两条线：**检索指标**（§检索基线）与 **RAGAS 内容相关性**。
会话 2：**评分一致性**（门禁为自研 harness——DeepEval 无现成的一致性/准确性 metric，见 SPEC §4.13 选型修正）。

## 基线

golden：31 条 query（18 条题库搜索形态 + 13 条学习推荐漏点形态）× 1972 条标注
（LLM 判级 + 复核）· `sha256 1e40a8d6e84a8cc266d28b657cb3c765c913da869a93cee51585e933c4402683`

| 变体 | NDCG@5 | NDCG@10 | Recall@5 | Precision@5 |
| --- | --- | --- | --- | --- |
| dense（单路稠密） | 0.787 | 0.688 | 0.157 | 0.929 |
| sparse（单路稀疏） | 0.749 | 0.694 | 0.157 | 0.916 |
| rrf（双路融合） | 0.783 | 0.716 | 0.161 | 0.942 |
| **hybrid（生产 = 融合 + rerank）** | 0.746 | 0.711 | 0.156 | 0.884 |

### 怎么读这张表（三条，与数字同等重要）

1. **Precision 高不构成「准」**：0.88–0.94 很好看，但池内口径下「相关」的门槛是 grade ≥ 1
   （相邻知识点也算），加上本库同题多——top-5 里塞进几条「相关」的并不难。**排在最前的是不是最该
   看的**，由 NDCG 回答，不由 Precision 回答。
2. **Recall 低是 top-k 的本质，不是检索漏了**：一条查询的池内相关候选常有几十条，top-5 最多装 5 条
   ——Recall@5 的结构性上限就在 5/N 量级（实测 ~0.16 是天花板，不是缺陷）。它衡量「一次给够不够
   看」，想问「有没有漏」，看 Recall@10 或加大 k。
3. **样本小，只读大差值**：31 条 query（missed_point 仅 13 条），变体间 0.01–0.02 的差距在抽样噪声
   以内——**只有 +0.045 / −0.152 这种量级的分叉才值得当结论读**（噪声地板管「同条件重复的抖动」，
   这条管「样本量撑不撑得起这个差」；两者都过头了才谈结论）。

### 结论一：rerank 的净贡献按查询长短分叉

| 场景 | rrf | hybrid | 净贡献（NDCG@5） |
| --- | --- | --- | --- |
| bank_search（短查询，18 条） | 0.761 | 0.806 | **+0.045** |
| missed_point（长查询：域名标签 + 多个漏点拼接，13 条） | 0.813 | 0.662 | **−0.152** |

域维度上 rerank 伤得最重的是 `tool-use`（0.785 → 0.633）与 `agent-architecture`（0.796 → 0.676），
受益的是 `rag`（0.788 → 0.823）与 `memory`（0.760 → 0.798）。

机制在最长的几条查询（就是那些漏点查询）上看得很清楚：查询问的是**工具设计原则**（单一职责 /
幂等 / 结构化返回），融合路排在首位的正是「怎么设计一个好工具」这类题，rerank 却把它踢到 15 名
开外、把「Function Calling 机制原理」这类题提上来——**交叉编码器被域名标签与关键词的字面重合
带偏**。学习推荐拼的正是这种长查询。

> 题面一律不在此文件出现（语料红线）：这里只写题型与档位，不引原文。

### 结论二：RAGAS 独立印证同一处短板

`ContextRelevance`（按**单条漏点**打分，13 组 / 67 条漏点）：总体 0.504，组间等权。
分域看 `tool-use` 0.217、`agent-architecture` 0.208 垫底，`planning-reasoning` 0.717 最好——
**与 NDCG 的域排序指向同一处**，两条独立指标互为佐证。

### 结论三：噪声地板

同一份 golden 连跑两次：`dense`/`sparse` **逐位一致**（本地嵌入 + Qdrant 是确定的），
`rrf` ±0.003、`hybrid` ±0.005（rerank 是远程 API）。**小于 0.005 的差值不要当结论读。**

**RAGAS 的噪声地板（2026-10-01 P1 收尾复跑补测）**：同输入（13 组 / 67 漏点）复跑，
总体 **0.504 → 0.520（+0.016）**——判官是 LLM，这个差是纯噪声。**读 RAGAS 时差值小于
~0.02 不下结论**（会话 1 当时没记这条，复跑才量出来）。

## 怎么用

```bash
cd backend
uv run python scripts/eval_retrieval_run.py --label <改动名>   # 结果落 data/eval/results/
```

重嵌、换 rerank 模型、改检索参数之后重跑同一条命令，对比两份 json 的 `overall`。两个前提：

1. **golden 哈希一致**——`retrieval_queries.json` 的内容哈希写在结果文件里，改了 golden 就不能直接比数字；
2. **差值大于噪声地板**（见上）。

## 复核记录

- 判级自一致率（抽样重判 8 条 query / 504 条判定）：**96.4%**
- 复核结论：**改 4 条**——`q18 #5`、`q21 #3`、`q27 #3`、`q27 #4`，全部 1 → 0（把「同一大主题、不同子方向」
  误判成了相邻档）。复核方式：逐条过 31 块 top-5 + 14 条「最该看的行」。
- **复核人是 Claude，用户未逐条审**；记录不冒充人工复核。
- 边界项（同一实体不同侧面）**保留原判**——逐个调等于换口径，而口径要跨版本稳定。
  理由与逐条明细写在 `retrieval_queries.json` 的 `review` 字段里。

## 已知边界

- **池内口径**：候选池 = 各变体并集，池外题目一律视作不相关。指标**跨版本可比**（同一份 golden、
  同一个池策略），**不能当绝对召回率读**。
- **本库同题多**：一条查询常有几十条相关候选 → Precision/MRR 这类指标分辨力有限（MRR 恒为 1.0，
  已弃用换成 Precision@k）。
- **纯域名回退的查询没法进这套指标**：域名标签查询除了 filter 不含信息，域内每题同等相关，
  分级标注无从谈起。它由 RAGAS 那一路覆盖（且 RAGAS 也「不适用」——没有要补的知识点）。
- **行为面场次不进**：`/recommendations` 对行为面直接返回空分组，检索 golden 与 RAGAS 都只看技术面。

# 评分一致性基线（P1-M12 会话 2）

> 同上：只有数字与结论。含题面/回答的产物（`golden/judge_items.json`、`judge_review.md`、
> `results/judge-*`）全部 gitignore。

## 是什么

评分官（LLM judge）的质量从「感觉还行」变成可重复的数字与门禁。三条线：**一致性**（同题同答
重复评 K 次，分数自己晃多少 = **噪声地板**）、**准确性**（vs 人审过的期望分）、**区分度**
（同一道题的弱/中/强三答是否单调）。**测的就是生产 prompt**：消息由 `judge.judge_messages`
构造、生产温度 0.3——评测与生产共用同一入口，由单测钉死逐字一致。

**期望分怎么来的**：`deepseek-v4-pro` 温度 0 按独立 rubric 预判（与评分官 flash 异模型）+
人工复核（**复核人记为 Claude，未冒充人工**）。**不用「当时实得」当基准**——那是评分官自己的
输出，等于自己给自己打分；实得只作对照。复核结论：37 条逐条过，**无一条需要改判**（边界项保留
原判，口径要跨版本稳定）。

## 基线（37 条 golden · 每条 5 次 · 生产温度 0.3 · golden sha256 `8d9afad7`）

| 指标 | 值 | 读法 |
| --- | --- | --- |
| 噪声地板 σ̄（逐题总分波动的均值） | **0.113** | 同一回答重复评 5 次，总分标准差约 0.11 分 |
| 完全一致率（5 次五维全同） | 0.324 | 抽样噪声 ≈0.077，只作参考 |
| 总分 MAE（vs 人审期望分） | **0.225** | 约为 σ̄ 的 2 倍——**误差大于晃动，信号成立** |
| 偏置（正 = 评分官偏高） | +0.017 | 基本无系统性放水/苛刻 |
| 维度命中率（\|均值−期望\| ≤ 0.5） | 0.778 | |
| 覆盖率比例误差（70% 追问线的输入） | 0.076 | 抗关键点改写 |
| 三档单调（同题弱/中/强） | **3/3 组** | 三档分数 2.0/3.0/4.2、1.4/3.0/5.0、2.0/2.2/3.8 |

**指标自身的重复性**（同一 golden 连跑三轮生产臂）：σ̄ 0.126 / 0.113 / 0.095 · 总分 MAE
0.227 / 0.225 / 0.209 · 偏置 +0.039 / +0.017 / +0.031。门禁余量即按此取 2–4 倍；门禁本身的
默认路径（第三轮）复验全过。

## 温度对照（实验——**没有改生产**）

> 该对照组跑自**另一轮**同 golden 运行（生产臂 σ̄ 0.126）——与主基线的 0.113 之差，
> 就是上表「指标自身的重复性」那一行。

| 温度 | σ̄ | 完全一致率 | 总分 MAE | 维度命中率 |
| --- | --- | --- | --- | --- |
| 0.3（生产） | 0.126 | 0.378 | 0.227 | 0.778 |
| 0.0 | **0.063** | **0.595** | 0.218 | 0.795 |

温度 0 把晃动砍半、准确性持平。**要不要改生产温度是独立决策**（影响评分/报告/PDF/能力曲线，
需单独回归），本会话不改——数据先摆在这里。

## 门禁

```bash
cd backend
uv run python scripts/eval_judge_gate.py                    # 跑生产臂再判（失败非零退出）
uv run python scripts/eval_judge_run.py --label <改动名>     # 只想看数字时
```

阈值 = 基线 + 余量；**golden 哈希变了 = 换基准**，门禁拒绝比较。改评分 prompt / 维度表 /
模型 / 温度之后必须跑。**完全一致率不进门禁**（抽样噪声比要抓的退化还大，会误报）。

## 已知边界

- **行为面只覆盖低-中分段**：真库行为面样本单题均值 1.6–3.8，无 ≥4 分样本——高分段的评分一致性未测；
- **5/8 条行为 golden 无关键点**：真库 14 道启用行为题里有 6 道 `key_points` 为空（**M11 遗留**的
  「怎么答」建议题，当年启用时就没带要点）——覆盖率指标对它们**不适用**（既不是 0 也不是 1），
  引擎里它们的覆盖率恒为 1.0，故基于覆盖率的追问决策对这类题无效。**归属 P2**：随 P2 补题库
  （补讲述要点或另行分类）一起处理，M12 只记录不修；
- **评测输入统一是「单轮回答」**：带追问的真实样本取合并后的最终答案，`followup_log` 恒「无」——
  追问过程中的评分不在覆盖范围内（重建中间轮次输入需要 trace，代价不值）；
- **评分官会截断/改写长关键点**（实测 7/185 与 3/185 次运行）：集合口径的覆盖率 F1 因此**偏低**，
  故另给「比例误差」口径；`unmatched_key_points` 计数进报告，不静默。
